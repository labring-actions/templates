# 百灵中枢 BailingHub

![百灵中枢控制台](https://raw.githubusercontent.com/labring-actions/templates/kb-0.9/template/bailinghub/website-screenshot.webp)

百灵中枢是一套开源的 Agent 业务动作治理控制面。它帮助已有的商城、CRM、ERP、SaaS 后台等业务系统接入 AI 助手，同时避免把业务密钥和最终权限直接交给模型。

接入后，可以统一管理 AI 能调用哪些接口、哪些动作需要人工审批、如何防止重复执行，以及每次业务动作如何审计和追踪。业务系统仍然负责最终权限判断。

## 此模板会部署什么

- 百灵中枢 `0.1.14`
- 由 Sealos 托管的 MySQL 数据库
- 一套确定性的演示业务服务，包含订单查询、售后工单、退款审批和故障 Trace 示例
- 一个可通过 HTTPS 访问的百灵中枢控制台

MySQL 和演示业务服务仅在集群内部访问，对外只开放百灵中枢控制台。

## 安装

1. 设置管理员用户名。
2. 填写一个强度足够、未在其他系统使用过的管理员密码，并妥善保存。
3. 部署模板。
4. 等待百灵中枢工作负载进入就绪状态。
5. 打开应用，使用部署时填写的管理员账号登录。

中枢内部 Token 和演示服务密钥由模板自动生成。

## 首次体验

模板会在第一次启动时写入演示数据。无需连接真实业务系统，即可观察一条完整的受治理执行链路：

- 查询演示订单；
- 创建演示售后工单；
- 让高风险退款申请进入人工审批；
- 在 Trace 中查看一个故意触发的业务工具错误。

演示数据和演示动作不代表真实生产集成。

## 安全边界

- 百灵中枢负责 Agent 能触达哪些能力，以及调用过程如何被治理。
- 最终用户权限、租户隔离和实时业务状态仍由业务系统判断。
- 初始化管理员密码只在首次创建管理员时使用，重启和升级不会重置已有管理员密码。
- 自动生成的 Token 保存在 Kubernetes Secret 中；连接生产系统前应按组织规范轮换。
- 不要把 MySQL 或演示业务服务暴露到公网。

## 升级

模板固定使用不可变的百灵中枢和演示业务服务镜像版本。升级时应通过经过审查的模板版本，同时更新两个镜像标签。

升级前请：

1. 备份 MySQL 数据库；
2. 阅读百灵中枢版本说明；
3. 在非生产环境验证目标版本。

## 备份与删除

应用状态保存在托管 MySQL 中，删除安装前请先完成备份。

请在 Sealos 控制台确认本模板创建的三类资源均已删除：

1. 百灵中枢主应用；
2. 集群内部的演示业务应用；
3. 托管 MySQL 数据库集群。

只删除主应用并不能保证独立托管的数据库已经被移除。请单独确认数据库删除结果，避免残留持久化数据和继续产生资源费用。
